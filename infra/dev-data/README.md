# 개발용 샘플 데이터

로컬 Compose에서 허브 기준 데이터를 재적재하거나 가상 업체를 적재·제거하는 도구입니다.

## 시작 시 적재되는 데이터

- `scripts/init-env.sh`는 `.env`를 생성합니다.
- `infra/postgres/01-init.sh`는 빈 DB 볼륨의 최초 기동 때 DB·스키마·계정을 준비합니다. 업무 테이블과 데이터는 각 앱이 준비합니다.
- 허브 앱은 `local` 프로필로 시작할 때 테이블 생성 후 `hub/src/main/resources/db/seed/`의 SQL로 허브 17개와 허브 경로를 자동 적재합니다.
- 가상 업체는 자동 적재하지 않습니다. 업체 앱을 시작한 뒤 기존 개발 계정의 관리자 UUID를 지정해 적재하세요. 이 도구는 사용자 계정을 만들거나 관리자 ID의 존재·권한을 확인하지 않습니다.

## 실행

저장소 루트에서 [처음 실행](../../README.md#처음-실행)에 따라 `.env`와 Compose를 준비합니다.
각 명령은 컨테이너의 서비스별 DB 계정을 사용하므로 로컬 `psql` 설치는 필요하지 않습니다.

```bash
# 허브 17개 재적재 (일반적인 앱 시작 때는 필요 없음)
bash scripts/dev-data.sh hubs

# 기존 개발 계정의 UUID로 가상 업체 34개 적재
bash scripts/dev-data.sh companies YOUR_MANAGER_USER_UUID

# 이 도구가 만든 가상 업체만 제거
bash scripts/dev-data.sh clear-companies
```

업체는 허브마다 2개씩 만들고 이름에 `[개발샘플]`을 붙입니다. 주소는 가상 값입니다.

## 반복 실행과 제거

- 업체는 `c0ffee39-0000-4000-8000-000000000001`부터 `...000000000034`까지 고정 ID와 생성자 `dev-seed`를 사용합니다.
- 재적재는 없는 업체만 추가하고 기존 이름·관리자·논리 삭제 상태를 보존합니다. 예약 ID를 다른 생성자가 사용하면 전체 적재를 중단합니다.
- 제거는 예약 ID와 `created_by = 'dev-seed'`가 모두 일치하는 업체만 물리 삭제합니다. 일반 업체와 허브는 보존합니다.
- 업체를 참조하는 상품·주문 등은 함께 지우지 않습니다. 연동 실험을 마친 뒤 제거하세요. DB 제약조건으로 제거할 수 없으면 해당 명령 전체를 롤백합니다.
- 각 명령은 한 DB의 단일 트랜잭션으로 실행하며 SQL 오류 시 롤백합니다. 기존 DB 볼륨의 비밀번호는 `.env`를 바꿔도 변경되지 않습니다.

업체 이름·주소는 [companies.sql](companies.sql)에서 수정합니다.
